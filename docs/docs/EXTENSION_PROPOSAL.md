# YYB Go 功能扩展建议书

## 1. 文档目的

本文档基于当前源码结构，评估 YYB Go 的后续扩展方向，重点关注安全性、可测试性和账号网络策略。

## 2. 当前系统现状

当前项目已经具备：

- 扫码接入账号
- 保存 `login_buffer` 和凭据
- 建立并复用协议会话
- 提供基础控制台页面
- 提供三类 wxapp 调用能力

当前项目的主要边界是：

- 没有后台鉴权
- 没有账号权限体系
- 没有来源 IP 控制
- 只有全局级别 `tcp_proxy`
- 缺少审计日志和操作留痕

## 3. 扩展优先级建议

我建议把扩展拆成三层推进。

### 第一层：安全与可控性

优先级最高，适合先做。

建议功能：

1. 管理后台鉴权
2. 操作审计日志
3. 账号删除、刷新、调用能力的权限控制
4. 来源 IP 白名单

原因：

- 当前服务直接暴露核心能力
- 任何可访问服务的人都能操作账号
- 一旦部署到多人可访问环境，风险会迅速放大

### 第二层：测试与网络策略

这是你前面提到的重点方向。

建议功能：

1. 账号级代理配置
2. 账号级固定出口策略
3. 调用链路可视化状态
4. 失败重试与路由策略配置

### 第三层：易用性与运维性

建议功能：

1. 账号分组与标签
2. 结果导出
3. 页面上的调用历史
4. 批量健康检查
5. 批量重扫提醒

## 4. 关于“指定账户使用指定 IP”的可行性

这个需求可以实现，但要先明确具体含义。

### 4.1 方案 A：指定账户走指定出口 IP

这是最符合当前项目结构的方案。

实现思路：

1. 在 `wechat_accounts` 表增加账号级网络字段，例如：
   - `proxy_type`
   - `proxy_addr`
   - `proxy_enabled`
2. 在扫码确认、会话建立、能力调用时，优先读取账号级代理配置。
3. 保持 `sessions` 表的 `(wechat_account_id, tcp_proxy)` 隔离方式。
4. 在页面中增加账号网络配置项。

为什么这条路最自然：

- 当前会话缓存已经把 `tcp_proxy` 作为区分维度
- `Pool.run`、`Pool.state`、`transport.go` 都已经支持代理值参与链路

实际前提：

- 需要你拥有真实可用的代理出口
- 代理出口对应你期望的公网 IP

应用层能做的是“选择哪条出口”，前提是这条出口真实存在。

### 4.2 方案 B：指定账户只能由指定来源 IP 操作

这是另一类需求，适合做访问控制。

实现思路：

1. 给账号增加允许来源 IP 列表。
2. 在 HTTP 层读取客户端 IP。
3. 在 `/accounts/*` 和 `/wxapp/*` 入口校验来源 IP 是否命中规则。
4. 命中失败时返回 `403`。

这个方案解决的是“谁可以操作账号”，它和“账号请求从哪个公网出口发出”属于不同问题。

## 5. 推荐的落地顺序

如果目标是“用于测试”，我建议按这个顺序推进：

1. 增加最小后台鉴权
2. 增加账号级代理配置
3. 增加来源 IP 白名单
4. 在页面上展示账号当前代理与最近调用状态
5. 增加调用日志

这个顺序的好处是：

- 先把系统收口
- 再把网络策略做细
- 最后再提升排障效率

## 6. 最小改造方案

如果只做最小可用版本，我建议范围控制在下面几项：

### 6.1 数据层

为 `wechat_accounts` 新增字段：

- `bound_proxy`：字符串，保存 `socks5://...` 或 `http-connect://...`
- `allowed_source_ips`：字符串或 JSON，保存来源 IP 列表

### 6.2 后端层

新增能力：

- 读取账号级代理配置
- 读取账号级来源 IP 限制
- 在调用前统一做账号策略解析

推荐做一个集中函数，职责包括：

1. 解析账号策略
2. 校验来源 IP
3. 计算本次调用使用的有效代理

### 6.3 前端层

在主控制台中增加：

- 账号详情抽屉或表单
- 代理配置输入框
- 来源 IP 白名单输入框
- 最近一次调用状态展示

## 7. 中期改造方案

如果后续要长期使用，建议继续增加：

- 用户系统和角色权限
- 审计日志表
- 调用历史表
- 账号状态监控任务
- 失败报警

## 8. 不建议直接做的方向

基于当前代码形态，我建议先避免这些高成本改造：

1. 一开始就做复杂 RBAC
2. 一开始就做分布式会话
3. 一开始就重写前端框架
4. 一开始就把协议层拆成独立服务

当前项目规模还不需要这么重的重构。

## 9. 结论

YYB Go 当前的最佳扩展路径很明确：

1. 先补鉴权和访问控制。
2. 再做账号级代理出口。
3. 再做测试友好的可视化和日志能力。

其中“指定账户使用指定出口 IP”具备直接扩展基础，因为当前会话缓存和协议调用流程已经天然支持 `tcp_proxy` 维度。
